CarlosIntrodução

Um hotel não pode vender o mesmo quarto duas vezes

O problema

  • Reservas que se sobrepõem no mesmo quarto
  • Hóspede colocado num quarto em manutenção ou pequeno demais
  • Dados de hóspedes, quartos e equipe espalhados

O objetivo

Centralizar a operação do hotel numa API que guarda tudo num só lugar e recusa os erros antes que eles cheguem ao banco.

Como o sistema está organizado

Arquitetura em camadas (MVC), pacote br.com.vesta. Cada requisição atravessa as camadas nesta ordem:

controller

Recebe

Um controller REST por entidade. Valida o JSON e responde com o código HTTP certo.

›
service

Decide

AlocacaoService aplica as regras de alocação de quarto.

›
repository

Busca

Interfaces JpaRepository com consultas derivadas do nome do método.

›
model

Guarda

Entidades JPA que viram as tabelas do H2.

Por fora de tudo, o GlobalExceptionHandler padroniza qualquer erro numa resposta JSON.

Funcionário

ThiagoEntidades e banco

As regras moram na entidade

@Entity
@Table(name = "hospedes")
public class Hospede {

  @NotBlank(message = "O CPF é obrigatório")
  @Pattern(regexp = "\\d{11}")
  private String cpf;

  @NotNull @Past
  private LocalDate nascimento;

  @ManyToOne
  @JoinColumn(name = "reserva_id")
  private Reserva reserva;

  @ManyToOne
  @JoinColumn(name = "dependencia_id")
  private Dependencia quarto;
}
  • Bean Validation nos campos: @NotBlank, @Pattern, @Email, @Past, @Positive
  • Mensagens de erro em português, prontas para o usuário
  • Relações N:1 com @ManyToOne: hóspede → reserva e quarto; dependente → hóspede
  • Status do quarto como enum StatusDependencia, gravado como texto: DISPONIVEL, OCUPADO, MANUTENCAO

GeorgeControllers e Swagger

O que a API recusa

  • Checkout antes do check-in
  • Hóspede em área comum ou em quarto em manutenção
  • Reserva com mais pessoas que a capacidade do quarto
  • Duas reservas com datas sobrepostas no mesmo quarto
  • Excluir reserva ou quarto que ainda tem hóspedes
  • CPF de funcionário repetido

Regra quebrada vira resposta clara, em vez de erro genérico:

HTTP 409 Conflict
{
  "erro": "O quarto já está reservado
           nesse período"
}

Campos inválidos voltam como 400 com a lista de campos e mensagens; JSON malformado e datas fora de AAAA-MM-DD também.

GeorgeControllers e Swagger

Swagger: a API testada pelo navegador

  • Dependência springdoc-openapi 3.0.3, a série compatível com Spring Boot 4
  • Nenhuma configuração extra: ele lê controllers e modelos e gera a documentação
  • Interface em /swagger-ui/index.html
  • Especificação OpenAPI em /v3/api-docs

Hóspedes e dependentes referenciam os “pais” só pelo id: "reserva": {"id": 1}

Demonstração

  1. Listar os quartos disponíveis no período
  2. Criar uma reserva nova
  3. Alocar um hóspede no quarto
  4. Tentar a mesma data de novo e ver o 409
